3. EXTERNAL REQUIREMENT (libraries and tools)
---------------------------------------------
  The pom.xml which records what the project depends on:

  Build
    - Maven, group "dev.loafcode", artifact "an-error-caused-a-bottleneck",
      version 1.0-SNAPSHOT
    - Java 17 (compiler source and target)
    - UTF-8 source encoding
    - Source folder is "src" instead of Maven's default src/main/java
    - exec-maven-plugin 3.4.0 with main class "Main", so the game can be run
      from Maven

  Sources credited inside pom.xml:
    - pom.xml template: Pravin's "A beginner's guide to pom.xml and Maven"
    - libGDX dependency entries: libGDX wiki (Maven integration)
    - org.json: mvnrepository.com

  VS Code launch settings (.vscode/launch.json):
    - Launch config "Launch Game" runs main class "Main"
    - JVM arg --enable-native-access=ALL-UNNAMED
    - On macOS it also adds -XstartOnFirstThread (required by the windowing
      library on Mac)

  First assets added (Oct 17):
    - src/assets/appIcon.png        (64x64 window icon)
    - src/assets/placeholderNode.png (300x300 stand-in node picture)

WHY libGDX
----------
  The game needs a window, a camera, input handling and UI widgets.
  libGDX provides all of these in Java, runs on all three major desktop
  systems, and has a ready-made UI toolkit (Scene2D), which suits a
  node-and-pipeline game.
